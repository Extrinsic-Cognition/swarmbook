# Direct SOL pre-mint access

Bronze is $10 equivalent and Golden Aiolos is $1,000 equivalent in native SOL on mainnet. The buyer reviews an exact 90-second quote, signs a Memo + System Program transfer, and pays the owner-confirmed recipient `3nJn2tnmR27xbkjzT49YnSnXL2KeddzM7CkEizYiKMba` directly. No custom program, deployment rent, merchant private key, escrow, token issuance or NFT issuance is involved. This receipt records pre-mint access; Harmony NFT completion remains a separate implementation.

The existing Cloudflare Worker serves the API and existing static assets. D1 holds immutable order terms, the pre-broadcast signature, and the finalized receipt. The signature is persisted with a compare-and-set before the first broadcast attempt. Recovery verifies or rebroadcasts only the identical signed transaction; it never signs a second debit. The serialized transaction must exactly equal the canonical one, including buyer, recipient, tier/order memo, amount and blockhash, and its Ed25519 signature must verify. Only a successful finalized mainnet transaction creates an entitlement/public profile. Finalization after quote expiry is accepted. Missing historical data stays pending rather than inviting a duplicate purchase.

A purchase starts at most six background finalization checks over 24 seconds. The browser checks at most five times while checkout stays open. There is no cron or idle polling. Recover with My purchases (the wallet's receipt history, read with its signed seat proof), or GET `/api/premint/orders/:id`; retry finalization with POST `/api/premint/orders/:id/verify`. Existing devnet escrow reservations remain at `/app/legacy-reservations.html` and retain their original local reveal secrets.

An order id opens nothing (THE SEAT PROOF, Oct 15 2026; `app/dl-direct-protocol.mjs`): it is in its payment's memo on mainnet. A buyer shows a seat with the wallet's own signature: the checkout has the wallet sign a Sign In With Solana message once when it connects (this host, the wallet, a random nonce, issued now, valid 30 days; no transaction, no fee) and sends the proof in the `x-seat` header. The Worker checks it in `verifySeatProof` (the exact text, host and origin, issue and expiry times against its own clock, the Ed25519 signature of the wallet named): `/api/premint/receipts` answers 401 without that wallet's proof, `/api/premint/holders` names no order id (a holder's key is its payment's signature), and the vault and the film's wall open by the proof's wallet's paid orders, never by an id. Nothing is stored and no key is the Worker's: a proof lives until its own expiry. The design, the numbers and the proofs are in `app/tracenet/LANDING.md`, THE SEAT PROOF.

THE TWELVE CHAIRS (Oct 17 2026, `app/mint-chairs.mjs`): `GET /api/premint/chairs` ranks the seven days' top donors at each request from the seats paid to the pinned recipient (as `/tank` counts them) and quoted before the close (the window is his launch day's, `app/dl-paywall.js` mintState, at the Worker's clock), one chair a wallet, at most twelve, a tie to the lower finalized slot. It answers `{chairs, rule, shows, phase, opensAt, closesAt, held: [{rank, usd}]}`, with a holder's X name and avatar only when he rules `profile` and the buyer gave one; no wallet address, order id or email. While his rule (`CHAIR_RANK`) is unanswered it reads nothing and holds no chair. One D1 read of the paid rows a request, no cache, no cron: the same cost profile as `/holders`.

An order may carry an optional buyer email (migration `0002_premint_email.sql`): the owner's private way to reach a buyer, since a wallet, a GitHub name and an X handle are not one. The Worker trims and validates it at ingress, stores it with the order it was given to, and returns it from no endpoint: `publicOrder` and the holders query name their fields, and a test reads every response. Read the contacts of paid orders with `npx wrangler d1 execute optimism-fit-premint --remote --config wrangler.optimism-fit.jsonc --command "SELECT tier,buyer,email,paid_at FROM premint_orders WHERE status='paid' AND email IS NOT NULL ORDER BY paid_at"`. The privacy notice does not yet say this address is collected; that line is the owner's.

THE SOCIETY'S CODES (Oct 16 2026; `app/dl-society-codes.mjs` is the law, migration `0003_premint_society.sql` the tables). Two codes in Crockford's base32 (0-9, A-Z without I, L, O, U; a hand's lookalikes read, case and dashes ignored). The REFERRAL CODE, 8 letters, is a paid seat's own, public, shared as `https://optimism.fit/?ref=<code>`: the page keeps a visit's code 30 days and the checkout sends it with the order; the Worker resolves it to the paid seat it belongs to and freezes that seat on the order (`premint_orders.referred_by`) at the order's making, before any payment; a code never issued, or the buyer's own, refuses the order with the reason. The CLAIM CODE, 12 letters, is a paid seat's one-time key to Harmony's box: drawn by the buyer with the wallet's seat proof (`POST /api/premint/tickets/:id/claim`, a fresh one each draw, its sha256 alone kept), redeemed once by Harmony from her Mac (`POST /api/premint/claims/redeem` `{claim, holder}`: no browser origin, the code is the authority) for the seat's long token (shown once, its sha256 alone kept) and her wallet becomes the seat's holder. `GET /api/premint/seat?buyer=` (x-seat) answers the wallet's paid seats as tickets (`society.ticket/1`: code, share link, the friends who paid under `referrals`, a `society.referrals/1` projection whose rows are `paid` until an issued seat stands behind them, whether Harmony holds it); `GET /api/premint/ticket` (x-ticket) answers Harmony's. Three front doors run on the Worker (`run_worker_first`: `/`, `/referral`, `/claim`) so a friend's `?ref=` reaches the page whole. No code and no token is kept in clear; no response carries another seat's order id. Rate limiting of the redeem door is the 60 bits of the code: nothing else here throttles. The browser loads `@solana/web3.js` 1.95.8 from unpkg only when a buyer signs, to hand the wallet a `Transaction` built from the canonical bytes. Try again." instead of running them. The hash is of `lib/index.iife.min.js` (459,805 bytes) taken from the npm registry tarball, whose own integrity (`sha512-sBHzNh7dHMrmNS5xPD1d0Xa2QffW/RXaxu/OysRXBfwTp+LYqGGmMtCYYwrHPrN5rjAmJCsQRNAwv4FM0t3B6g==`) matches the registry's; unpkg and jsDelivr serve the same bytes. A new version needs a new hash: the command sits beside the constant in `app/dl-direct.js`. unpkg stays a third party in the signing path: it sees the buyer's IP address at that moment, and while it is down no payment can be signed. Serving the file from this site would end both and means shipping the bundle's license notices; that choice is the owner's.
